# 图片高保真前端复刻

以参考图片为唯一视觉目标。让模型理解和生成，让工具测量与验证，让用户审核实现策略与视觉结果。默认混合实现，不默认全部 CSS，也不默认全部图片。

## 0. 首阶段硬门禁：先分析、向用户说明、停止等待

**首次接到复刻任务，必须加载 `references/analysis-spec.md`，完成其中的八段固定格式说明，直接发在聊天中，然后结束本轮，等待用户审核。不能只说“先分析一下”，不能仅输出内部 JSON 或文件链接。**

1. 先读取原图；确实看不清时说明具体区域，不凭文件名猜画面。
2. 分区域检查布局、主要元素、所有可辨文字、素材、层级、裁剪与特殊字体。复杂图片结合局部图，不只描述“左边卡片、右边插画”。
3. 逐项说明什么用 HTML/CSS，什么用 SVG，什么复用原素材／裁切，什么需要 AI 抠图／图片编辑，什么才考虑 AI 生图，以及理由、替代方案、误差风险和当前工具是否具备能力。
4. 明确目标画布、视口、交互及必须可编辑的区域。所有估算标记待核验；用户批准方案不代表坐标已经精确测量。
5. 说明不需要生图时写“本图暂不需要 AI 生图”，缺工具时写“当前不可执行”，不能承诺不存在的抠图能力。
6. 分析可只在聊天中呈现，不强迫用户先打开文件。只有经授权的网格／局部观察副本可在分析时生成；不得提前写页面、搭骨架、创建工程、安装依赖、生成角色或制作正式素材。
7. 结尾固定询问：“请审核以上拆解，尤其是代码与图片素材的分工。可以指出需要修改的项，或确认按本方案继续；我会在收到确认后再制作素材和实现页面。”

**审核规则不可被快速模式跳过：**

- 初始请求中的“直接做”“完整实现”“不用问”不等于批准尚未展示的分析；仍须先展示并等待。
- 只有在已展示本次分析后，用户明确说“按这个方案继续／分析没问题，开始做”等，才进入批准范围。用户只同意某区域时，只实施该区域。
- 用户纠正分析时，更新受影响部分及实现分工，再等待确认；不能边解释边动工。
- 更换参考图、目标视口、主要布局、素材来源或从提取改为生图时，使受影响方案失效并重新审核。
- 延续任务可复用同一原图和已确认版本的记录；必须能追溯实际用户回复，不自造审批证据。

## 1. 固定不可变边界

- 不美化、改版、增删参考内容，不用整图背景冒充代码复刻。
- 普通说明、表单、按钮和需更新文字使用真实节点；装饰性特殊字只有明确批准才能图片化，保留可访问文字说明。
- 原素材优先于重新生成；近似生成逐项批准，标记来源，不保证与原角色一致。
- 不把置信度、OCR 候选、用户策略确认写成精确测量或最终视觉通过。
- 无同视口真实截图及实际对比，不宣称 1:1；机器差异率不等于视觉评分。
- 默认局部补丁，不整页重写，不替换已批准素材，不修改冻结区域后省略回归。
- 仅操作授权项目及输入；默认不覆盖原图、已有源码或证据，不自行安装、上传、登录或提交 Git。

## 2. 用户批准后固定执行协议

加载 `references/workflow.md` 的规格、审核回执和路径约定；加载 `references/model-compensation.md` 的小任务协议。在已批准目录记录 `analysis.json`、文字／素材清单和实际用户审核回复，固定技术栈、版本、组件接口与共享样式。

使用脚本的绝对路径；文档相对路径均以技能目录为基准，项目路径均以批准项目目录为基准。不要在用户工程中直接运行不存在的 `scripts/...`。

按实际功能检查环境：

```bash
python "<技能目录>/scripts/check_environment.py" --capability reference-preprocessing --capability asset-inspection --capability browser-screenshot --capability image-comparison --capability project-validation
```

`ready` 仅表示依赖发现；`partial` 继续可用功能；缺失项不假装已运行。详细恢复见 `references/setup-guide.md`。Python Playwright 为可选严格截图后端，未安装不自动安装，优先使用宿主现有浏览器能力。

## 3. 按阶段实现，不跨阶段扩张

| 阶段 | 必须执行／产出 | 进入下一步条件 |
|---|---|---|
| A 详细分析与审核 | 聊天八段说明、稳定元素 ID、分区策略、未确认问题 | 用户明确批准本次版本和实施范围 |
| B 固化规格 | 原图摘要、源像素坐标、文字清单、审核回执 | 规格一致性校验通过；不伪造核验状态 |
| C 素材处理 | 批准的复用／裁切／抠图／生成，素材清单及透明预览 | 实际看图批准，文件存在且来源可追溯 |
| D 布局骨架 | 主区位置、比例、层级；未就绪图片仅占位 | 主区截图检查通过，不先精修装饰 |
| E 页面集成 | 真实文字、重复组件、已批准素材、字体和裁剪 | 页面可运行，无未处理关键资源错误 |
| F 截图与校正 | 当前截图、截图报告、叠加、分区差异、局部任务卡 | 每轮重新验证目标、相邻、冻结区域 |
| G 交付 | 源码、素材、启动方式、证据及剩余差异 | 分别说明结构和视觉状态，不替用户批准 |

### 规格与素材校验

加载 `references/implementation.md`。使用 `validate_project.py --stage implementation` 核对原图摘要、当前审核版本、批准范围、文字与素材。它只检查明列文件和声明一致性，不能证明真实用户授权或抠图质量；必须同时核对实际聊天回复。

未核验文字不得定稿；字体未知保持待核验；复杂插画不强行 CSS 描画。素材脚本只能检查透明度，不能抠图。未批准素材可以占位，不当作正式素材集成。

### 真实截图与差异

加载 `references/verification.md`。设置一致的物理像素尺寸、CSS 视口、DPR、字体、初始状态；优先宿主浏览器，或明确选择严格后端：

```bash
python "<技能目录>/scripts/capture_page.py" --url "http://127.0.0.1:3000" --output "<项目目录>/screenshots/round-01.png" --width 1536 --height 864 --device-scale-factor 1 --backend playwright
python "<技能目录>/scripts/compare_images.py" --reference "<项目目录>/reference/source.png" --current "<项目目录>/screenshots/round-01.png" --output-dir "<项目目录>/screenshots/round-01-comparison" --regions "<项目目录>/reference/preprocessed/regions.json"
```

示例尺寸不是默认目标，必须替换为已确认尺寸。严格截图会核验新 PNG、实际尺寸、字体／图片就绪与连续稳定帧，并记录错误、版本和元素 AABB；CLI 降级只证明图片有效，明确保留就绪未验证，不能改写为严格通过。

### 局部修改与回归

先诊断，再修复。默认一次一个区域、最多三个相关问题，明确元素、允许文件和 CSS 属性；冻结或扩大范围前重新取得对应许可。按“几何→素材与文字→细节”校正，P0/P1 优先。

使用版本化截图，不反复覆盖 `current.png`。保存已列文件的检查点摘要；用 `validate_project.py --stage regression` 检查非授权已追踪文件和冻结区域变化。`needs_review` 表示需要复查，不代表视觉自动失败；脚本不能证明允许文件内每条 CSS 修改都合法，宿主还须检查完整 diff。

连续两轮同类问题无改善，先缩小到单元素并检查测量、字体或素材原因，必要时更换分工；不要无限整体重写。细节见 `references/model-compensation.md`。

## 4. 交付与停止

```text
实现位置与启动方式：
参考图／方案版本及用户批准范围：
目标视口、DPR与实际截图尺寸：
结构验收：通过 / 未通过 / 未验证
视觉验收：通过 / 未通过 / 未验证；实际审核人及依据
运行与截图：严格就绪 / 已截图但就绪未验证 / 未截图
证据：当前截图、报告、叠加、分区对比、修改与回归记录
剩余差异：元素 ID、原因、是否获得保留许可
未覆盖范围及下一步：
```

没有当前分析的用户确认、关键尺寸不明确、近似生成未授权、核心输入不可读、规格／截图不匹配或结果不可信时，停止受影响阶段。缺工具时说明降级和未验证项，不用模型猜测顶替证据。始终把实际分析及最终对比呈现给用户。
