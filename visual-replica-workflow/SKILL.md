# 图片高保真前端复刻

## 目标与边界

以用户提供的参考图片为唯一视觉目标，按固定阶段产出可运行代码、素材和真实验证证据。默认采用 HTML/CSS 处理文字与布局、SVG 处理简单矢量图形、独立图片处理复杂插画的混合方案。

1. 不擅自改版、美化、增删内容或改变交互含义。
2. 不把整张参考图作为页面背景、单张页面图片或内嵌大图冒充代码复刻。
3. 不把模型估算的坐标当作精确测量值；为估算项标记置信度，并通过截图校正。
4. 不用重新生成的近似素材替代可以提取的原图素材；近似重建必须先征得用户同意并明确标记。
5. 没有同视口浏览器截图和实际对比，不宣称完成 1:1、像素级一致或视觉验收。
6. 不用像素差异率代替用户的视觉判断；差异图只用于定位，不自动判定质量。
7. 每轮只修一组相关问题，不整页推倒重写，不为了修一处而破坏已通过区域。
8. 无参考图的全新 UI 设计、单纯修图和与参考图无关的普通前端开发不使用本流程。
9. 能由图片处理、文件检查或浏览器确定的事实，不让模型猜测；必须靠视觉判断的内容，拆成局部任务并保留用户验收。
10. 视觉指标只用于定位，不作为自动通过线；实际产出和对比材料必须交给用户判断，不代替用户宣布方案不可行。

## 1. 登记任务与授权

先确认以下输入；只缺非关键项时继续，缺关键项时只问最影响下一步的问题。

- 参考图片及其可读文件路径。
- 项目目录和允许修改的范围。
- 目标类型：A 类静态宣传图、B 类真实 UI 页面、C 类宣传图嵌 UI 的混合场景。
- 目标视口：宽、高、设备像素比；未提供时不得把宣传图比例擅自当成手机页面尺寸。
- 交互要求、必须真实文本化的区域和允许保留为图片的区域。
- 是否已有工程、设计规范、字体和素材。

固定画布任务可以把原图像素尺寸作为建议视口，但须经用户确认。响应式任务必须先明确目标设备视口和响应式行为。A 类优先视觉一致性，B 类优先真实组件和交互，C 类按区域分别制定文字、素材和组件策略。

加载 `@references/model-compensation.md`，根据任务类型和模型在实际图片上的表现选择补偿强度。新模型、新图片类型或连续出现识别错误时，先做轻量准入测试；同类任务已稳定或用户只要快速结果时可跳过，不为测试阻塞主流程。

遵循用户现有项目的修改约定。修改已有工程前，先给出分析和实施计划，取得确认后再写代码；只读分析可以直接进行。不得读取未授权目录，不得静默覆盖源码、素材或截图。

## 2. 检查能力与路由

视觉分析前确认宿主能够读取图片。无法读取时，请用户提供已有分析规格或更换可读图片；不得凭文件名猜测画面。

进入图片预处理、素材检查、截图或图片对比阶段前，从本技能目录按本次实际功能运行只读检查，例如：

```bash
python scripts/check_environment.py --capability reference-preprocessing --capability asset-inspection --capability browser-screenshot --capability image-comparison
```

按结果处理：

- `ready`：直接进入验证，不重复配置教程。
- `partial`：继续可用阶段，只说明受影响功能和降级。
- `needs_setup`：只展示本次缺失项，等待用户配置后重检。
- `unavailable`：区分版本、权限、浏览器、文件或服务故障，给出恢复方式和降级。

环境检查不证明页面能运行，也不证明浏览器截图成功。每个实际结果单独记录。

## 3. 按阶段执行

### 阶段 A：视觉逆向分析

加载 `@references/analysis-spec.md`。先保留原图并生成坐标网格、命名分区裁剪和区域清单，再结合整图与局部图输出画布规格、布局树、元素坐标与样式、独立文字清单、素材清单、待确认问题和风险排序。

- 给每个可识别元素分配稳定 ID。
- 同时记录像素坐标、相对坐标、层级和遮挡关系；局部坐标必须换算回原图坐标。
- 坐标和样式记录 `source`、`confidence`、`verified`，文字单独记录识别来源与核验状态。
- 区分直接可见事实与推测；无法辨认的文字标记待核验，不猜写。
- 本阶段不写 HTML、CSS 或 JavaScript。
- 关键区域、文字和目标尺寸未经用户核验时，不进入高成本素材制作。

### 阶段 B：素材盘点与处理

加载 `@references/implementation.md` 的素材部分，按以下优先级处理：

1. 复用用户已有原始素材。
2. 从参考图裁剪或提取，保留原图并输出独立文件。
3. 清理透明背景与边缘，检查耳尾、毛发、细线等细节。
4. 原图无法提供可用素材且用户同意时，才生成近似替代品。

为每项素材记录来源、用途、原图区域、目标比例、显示尺寸、透明状态、文件名和是否近似重建。用素材检查脚本核验真实 Alpha 通道、内容边界并生成深浅背景预览；自动结果只证明机器可检项，边缘和细节仍由用户看图验收。未标记 `approved: true` 的素材不得作为已确认资源集成。不要把多个独立角色挤在一张图里再期待精准拆分。

### 阶段 C：布局骨架

根据已核验规格搭建可运行骨架，先验证主区域尺寸、分栏比例、位置、间距、对齐、层级和遮挡，不在此阶段精修复杂插画。

固定技术栈、素材路径、组件接口和共享视觉变量。按“结构与引用表→主布局→重复组件→素材与细节”分次交付，每次列出修改文件、完成项和待验证项；当前阶段未通过检查，不让模型继续扩张修改范围。

固定画布采用设计尺寸容器和分层定位；规则列表采用 Grid；卡片内部采用 Flexbox；真实响应式应用不得简单依赖整页缩放冒充响应式。

### 阶段 D：素材集成与页面完成

加载 `@references/implementation.md` 的编码部分：

- 集成真实文本、样式和素材，保持元素 ID 或稳定选择器可追踪。
- 检查图片比例、透明留白、裁剪、字体回退、换行、层级和遮挡。
- 重复卡片可组件化，但组件化不得改变视觉结果。
- 集中维护颜色、间距、圆角和字体等视觉变量。
- 启动页面并记录启动方式、资源缺失和控制台关键错误；不能运行时只交付结构版本并标记未验证。

### 阶段 E：截图对比

加载 `@references/verification.md`，在原图与实现使用相同宽高、缩放和设备像素比后截图。

优先使用宿主已有的浏览器自动化能力；不可用时，经用户确认命令、URL、输出路径和浏览器进程影响后运行：

```bash
python scripts/capture_page.py --url "http://127.0.0.1:3000" --output "screenshots/current.png" --width 1536 --height 864
```

脚本不会启动开发服务器、安装浏览器或读取个人浏览器资料。HTTP/HTTPS 页面会产生相应页面访问；不可联网或不可启动浏览器时，提供手动截图步骤并标记未完成自动验证。

两张图都为受支持 PNG 且尺寸一致时，经用户确认输出目录后运行：

```bash
python scripts/compare_images.py --reference "screenshots/reference.png" --current "screenshots/current.png" --output-dir "screenshots/comparison"
```

尺寸不一致时先修正视口，不静默拉伸其中一张。工具不支持图片格式或无法生成差异图时，改为人工对比并明确限制。

### 阶段 F：分级校正

把参考图、当前截图、叠加图和差异图一起检查；复杂页面同时使用按区域生成的局部三联图，只报告实际可见差异，并关联元素 ID 或区域。

按“几何关系→素材与文字→精细细节”三轮校正，并在每轮内按 P0 整体结构、P1 主要元素与素材、P2 文字排版、P3 精细装饰排序。每轮用 `issues.md` 固定允许修改的元素、文件和属性，已验收元素标记 `approved` 且 `freeze: true`；非必要不得修改，确需修改时扩大回归范围。

诊断与修复分开：先形成问题清单，再实施局部补丁。修改后重新运行和截图，检查目标、相邻和冻结区域；出现退化时回到最近验收检查点，不叠加整页改动。

不得仅凭代码审阅宣布修好了，也不得因存在合理差异就擅自否定用户选择的方案。把实际结果和对比图交给用户判断。

## 4. 阶段交付物与通过条件

| 阶段 | 必须产出 | 通过条件 |
|---|---|---|
| 输入登记 | 原图、任务类型、目标尺寸、交互与修改范围 | 目标明确且授权清楚 |
| 分析预处理 | 网格图、分区裁剪、区域清单 | 原图保留且区域坐标可追溯 |
| 视觉分析 | 分析规格、布局树、文字和素材清单 | 关键区域与文字已核验 |
| 素材处理 | 素材目录与素材清单 | 主要素材均有明确实现方式 |
| 布局骨架 | 可检查的结构版本 | 主区域位置、尺寸和层级正确 |
| 页面集成 | 可运行页面和启动说明 | 无缺失资源和关键运行错误 |
| 视觉校正 | 同视口截图、对比材料、差异清单 | 明显差异已处理或经用户保留 |
| 最终交付 | 源码、素材、截图、验收与已知差异 | 验收状态真实、证据齐全 |

完整目录约定和角色分工见 `@references/workflow.md`。

## 5. 验收与交付

分别给出两档结论：

- **结构验收**：布局、元素顺序、文字内容和运行状态满足要求。
- **视觉验收**：完成真实截图对比，明显偏差已修正，剩余差异及原因已记录。

任何未完成项必须写成“未验证”或“部分验证”，不得写成通过。视觉指标只能辅助定位，不能替代验收清单和用户判断。

最终按以下格式交付：

```text
实现位置：
启动方式：
目标视口：
结构验收：通过 / 未通过 / 未验证
视觉验收：通过 / 未通过 / 未验证
已生成证据：源码、素材、当前截图、叠加图、整图与分区差异图、差异清单
剩余差异：逐项说明元素 ID、原因和用户是否需要决定
回归状态：目标、相邻和冻结区域的检查结果
未覆盖范围：
```

## 6. 停止条件

出现以下情况时停止受影响阶段，不用猜测结果顶替：

- 参考图不可读且没有可用分析规格。
- 目标尺寸或修改授权缺失，继续会改变核心结果。
- 素材只能近似重建但用户未同意。
- 页面必须实际运行或截图验收，而当前环境无法完成且用户不接受降级。
- 脚本要求覆盖已有文件、访问额外目录或执行未确认命令。
- 对比图尺寸不一致、格式不支持或输出不可信。
