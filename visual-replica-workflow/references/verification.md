# 真实截图、差异定位与回归

## 固定比较条件

先确认原图实际物理宽高、CSS 视口、DPR 和静态状态。自动比较要求 `sourceWidth = viewportWidth * DPR`、`sourceHeight = viewportHeight * DPR`，不隐式取整、不拉伸输入。固定字体、浏览器版本、操作系统、页面 URL 和初始状态；未知原图 DPR 不能凭空填成测量事实，应由目标视口与图尺寸共同确认。

参考图尺寸与页面目标不同、需要裁掉宣传边框或重排为手机应用时，先让用户批准新的比较基准；不能用跨尺寸差异率证明复刻成功。

## 截图路径与能力分级

优先使用宿主已有浏览器自动化。明确等待页面、字体、图片和目标状态，保存实际截图与报告；不能只凭页面代码判断。浏览器工具不可用时选择技能脚本，默认不安装软件，不启动开发服务器，不读取个人浏览器资料。

```bash
python "<技能目录>/scripts/capture_page.py" --url "http://127.0.0.1:3000" --output "<项目目录>/screenshots/round-01.png" --width 1536 --height 864 --device-scale-factor 1 --backend playwright
```

数字只为示例，替换为已确认尺寸。可选 `--ready-selector` 等待本轮可见元素，`--report` 指定报告路径，默认 `round-01.png.capture.json`。进程预算固定 45 秒，单项严格操作最多 10 秒；旧 `--timeout` 仅接受 45，不无限重试。

| 后端 | 依赖与行为 | 证据边界 |
|---|---|---|
| `playwright` | 已安装 Python Playwright 与可执行本地 Chromium 浏览器；不下载 | 等字体、图片解码、静态状态、连续两帧一致，采集错误与 DOM |
| `cli` | 本地 Chrome／Chromium／Edge 命令行 | 仅核验新 PNG 和物理尺寸；字体、DOM、CSS 视口与稳定性未验证 |
| `auto` | 有 Python Playwright 时选严格后端，否则 CLI | 报告实际后端；严格运行失败不偷偷降级后宣称通过 |

`--wait-ms` 只给 CLI 虚拟时间预算，不是字体／图片就绪证明。用户需正式严格证据时指定 `--backend playwright` 或使用已具备能力的宿主工具；CLI 是明确的降级，不伪造严格报告。

脚本在隔离临时目录生成全新截图，解码确认实际尺寸后才发布，避免旧 PNG 被误当新证据。报告含 PNG 摘要、实际尺寸、请求与观察到的视口／DPR、后端、字体状态、错误、浏览器版本、系统、UTC 时间以及 `[data-replica-id]` 的 AABB。Windows JSON 文件路径统一用正斜杠。

严格截图不超过 512 个元素标识，不静默截断；大量重复细节可按已分析的共同结构分组。DOM AABB 是变换后包围盒，不等于旋转前布局框。字体处于 loaded 不证明字体是原图的字形或字体家族，仍须视觉核验。

## 运行结果解释

- `captured`：当前 PNG 和严格就绪通过，**不是视觉验收通过**。
- `captured_not_readiness_verified`：CLI 可有有效 PNG，保留未验证限制。
- `captured_with_resource_errors / unstable`：可留下当前证据，但不能当作严格通过。
- `unavailable`：生成、尺寸、解码、超时或发布失败，不能声称成功。

严格正常或 CLI 降级成功退出 0；严格存在错误／不稳定退出 1；生成或发布失败退出 2。截图与报告逐文件发布，不能共同原子保证；发生部分发布时检查错误及 `published`，用 `png_sha256` 核对配对，不把旧报告与新图片混合。

输出默认不覆盖，优先使用 `round-01 / round-02`。只有明确批准覆盖才使用 `--overwrite`。URL 支持 HTTP／HTTPS／file，不收用户名、密码或常见敏感查询参数，报告对其他 query 值脱敏。HTTP 页面可能请求其自身资源，不能把“本地脚本”误称为绝不联网。

## 图像对比

自带图片处理仅支持 8 位、非交错的常见 PNG，保留原文件；JPEG 等必须经批准先转换同尺寸 PNG，不自动放大、裁切或拉伸。解码错误与区域越界明确失败，不伪造对比图。

```bash
python "<技能目录>/scripts/compare_images.py" --reference "<项目目录>/reference/source.png" --current "<项目目录>/screenshots/round-01.png" --output-dir "<项目目录>/screenshots/round-01-comparison" --regions "<项目目录>/reference/preprocessed/regions.json" --background "#ffffff"
```

`--regions` 可省略；其矩形坐标必须是原图源像素，不是放大裁图上的像素。`--background` 用统一不透明背景合成透明图后比较，默认白色，报告记录实际模式和背景。完全透明像素的隐藏 RGB 不计入可见差异；白背景可能遮住部分透明度差异，透明素材仍单独做 Alpha 和深浅背景检查。

输出 `overlay.png`、`diff.png`、`comparison.json`；指定区域时另有 `regions.json` 和每区原图／当前图／差异／三联图。源图只读；默认不覆盖已有文件，明确拒绝输入的路径别名、符号链接和硬链接输出。

每像素微小颜色变化都可能被标记，抗锯齿和纹理会放大差异。区域差异率只帮助安排检查顺序，不自动判失败或承诺 1:1。输出有数量／像素预算，超限缩小实际分析范围，不用静默省略失败区域的方式通过。

## 差异诊断与局部校正

把整图、当前图、叠加和差异一起观察，复杂区域同时提供局部三联图。只报告实际可见问题：

```text
区域／元素 ID：
实际观察：当前相对原图的方向、尺寸、文字、素材或样式偏差
直接证据：本轮截图与局部区域
优先级：P0整体结构 / P1主要元素素材 / P2文字 / P3细节
候选原因：不确定则标明待检查，不先猜定 CSS
建议修改：实际文件、选择器、属性或素材
验证方法：目标、相邻、冻结区域的重新截图
```

按几何关系 → 素材与文字 → 精细细节分轮，默认一次一个区域最多三个相关问题。先诊断，后局部修改；不要每次“整体优化到1:1”。字体变化影响父容器和相邻元素时扩大回归，不以冻结规则阻止必要修改，也不默默更改已验收结构。

## 阶段校验与回归

`workflow.md` 给出 `validate_project.py --stage capture / regression` 命令及问题清单、文件检查点格式。只有实际严格报告可进入 capture 机器检查；宿主报告需由真实工具结果提供同等字段，不由模型凭空填 verified。手动截图可支持人工视觉检查，但不伪装成宿主严格报告。

回归检查当前 PNG 与已确认基线、明列源码和素材摘要；冻结区域有像素变化返回 `needs_review`，交用户复查，不自动判视觉失败。文件 hash 只能检查明列文件，不能证明未列新增文件或允许文件内的每条属性修改均合法；宿主还需检查完整 diff。

## 最终验收

分别检查画布／视口、主布局、文字与字体、素材比例与边缘、颜色与细节、运行／交互、修改与回归、交付完整性。结构通过表示布局与运行范围满足要求；视觉通过必须有实际同视口对比、剩余差异和用户判断。局部批准、脚本退出 0、截图文件存在均不能替代完整验收。
