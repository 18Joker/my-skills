# 截图对比、修正与验收

## 截图一致性

原图和实现截图必须具有相同宽度、高度、设备像素比和目标缩放。等待页面资源、图片和字体加载完成；固定动画或选取用户确认的静态状态。

截图前记录：页面 URL 或 HTML 文件、浏览器、视口、设备像素比、等待方式、字体状态和截图时间。不要比较不同尺寸的图，也不要为了得到差异图而静默拉伸。

## 工具顺序

1. 使用宿主已有的浏览器自动化能力，明确等待字体和页面就绪。
2. 不可用时使用技能自带截图脚本。脚本只支持 HTTP、HTTPS 和本地文件 URL，使用临时浏览器资料目录，不读取用户浏览器账号数据。
3. 浏览器不可用或页面需要复杂交互时，给出手动步骤，让用户提供同视口 PNG；标注未完成自动截图。

截图脚本示例：

```bash
python scripts/capture_page.py --url "http://127.0.0.1:3000" --output "screenshots/current.png" --width 1536 --height 864 --wait-ms 3000
```

运行前向用户说明实际 URL、输出路径、浏览器进程和页面访问范围。输出已存在时默认停止；只有用户明确同意覆盖后才添加 `--overwrite`。

本地 HTML 可直接使用 `file://` URL。依赖模块加载或本地接口的页面应由用户确认开发服务器启动方式，不为简单预览额外引入常驻服务。

## 图片对比

自带对比脚本仅使用 Python 标准库，支持 8 位、非交错 PNG 的常见颜色类型。它不读取 JPEG、不修改输入图片，并拒绝尺寸不同的输入。

```bash
python scripts/compare_images.py --reference "screenshots/reference.png" --current "screenshots/current.png" --output-dir "screenshots/comparison"
```

复杂页面可附加预处理阶段生成的区域清单，输出局部核验材料：

```bash
python scripts/compare_images.py --reference "screenshots/reference.png" --current "screenshots/current.png" --output-dir "screenshots/comparison" --regions "reference/preprocessed/regions.json"
```

输出：

- `overlay.png`：两张图各 50% 混合，位置不重合会出现双边轮廓。
- `diff.png`：红色突出差异区域，灰度区域便于观察位置。
- `comparison.json`：尺寸、整图差异和通道差值信息。
- `regions.json`：各命名区域的差异定位信息。
- `regions/`：各区域的原图、当前实现、差异图及三联图，便于局部诊断。

区域指标只用于安排检查顺序，不能据此自动判定某个区域失败。区域清单坐标越界、图片尺寸变化或局部材料未生成时，明确报告，不静默拉伸或省略失败状态。

这些数字只用于定位，不能等同视觉质量，也不能作为自动通过或否定方案的门槛。抗锯齿、字体渲染和合理细节调整都可能产生像素差异。

输出文件存在时默认停止；只有用户明确同意覆盖后才添加 `--overwrite`。格式不支持时，先保留原图，由用户确认转换方式；不得假装已经生成对比材料。

## 分区核验

整图复杂时，按标题、主面板、角色卡片、底部装饰等区域分别检查。优先使用原图局部、当前实现局部和差异局部组成的三联图；模型无法从整图稳定定位时，进一步缩小到单个区域或元素。每个差异尽量关联分析 ID 和原图坐标，避免局部问题被整体观感掩盖。

差异分析提示词：

```text
比较参考图和本次实现截图。不要重写整个页面，不提出主观美化建议，只识别实际可见差异。

按以下格式输出：
1. 元素 ID 或所在区域
2. 当前截图的问题
3. 相对参考图的偏差方向、尺寸或样式差异
4. 修正优先级
5. 建议修改的 CSS 属性、素材或组件

优先报告影响面积大、位置偏差明显的问题。无法确定原因时明确标记，不臆测。不要把抗锯齿或用户允许的细节调整自动判为缺陷。
```

## 三轮校正与优先级

| 轮次 | 主要目标 | 本轮边界 |
|---|---|---|
| 第一轮：几何关系 | 画布、主区域、面板、卡片、遮挡和层级 | 不因精修阴影或字体而改动已确认结构 |
| 第二轮：素材与文字 | 插画比例、透明边缘、裁剪、文字内容、字体和换行 | 不随意改动已确认的几何坐标 |
| 第三轮：精细细节 | 颜色、边框、阴影、渐变和小装饰 | 每次只选少量相关问题 |

每轮内部再按以下优先级排序：

| 优先级 | 范围 | 典型问题 |
|---|---|---|
| P0 | 整体结构 | 画布比例、分栏、主面板、背景、留白 |
| P1 | 主要元素与素材 | 卡片位置与大小、插画比例、裁剪、遮挡、层级 |
| P2 | 文字排版 | 字体、字号、字重、行高、换行、字距、对齐 |
| P3 | 精细装饰 | 阴影、渐变、边框颜色、小图标和手绘线条 |

诊断与修复分开。先把问题写入 `issues.md`，固定允许修改的元素、文件和属性，再实施局部补丁。修正后重新运行、截图和对比，检查目标、相邻区域和 `freeze: true` 的已验收区域。不要整页推倒重写。

出现退化时回到最近验收检查点，只重做当前小组修正。恢复或覆盖文件前列明对象和影响，取得用户确认。

## 验收清单

### 画布与视口

尺寸、比例、缩放、设备像素比和边缘裁切符合目标。

### 主要布局

面板、卡片和文字区的相对位置、尺寸、顺序与层级正确。

### 文字内容

无遗漏、错误、意外换行或未记录的字体回退。

### 素材一致性

插画、图标和背景来源正确，无异常裁剪、拉伸或透明边缘问题。

### 视觉细节

颜色、圆角、边框、阴影、叠放和间距经过实际对比。

### 运行质量

页面能够启动，无缺失资源和关键控制台错误，交互范围符合登记要求。

### 修改与回归

本轮只修改任务卡允许的范围；目标、相邻和冻结区域均有复查结果。出现的退化已恢复或明确记录，没有未经说明的额外改动。

### 交付完整性

源码、素材、启动说明、最终截图、差异清单和已知限制齐全。

## 两档结论

**结构验收**：主要区域、元素尺寸、顺序、文字和运行状态满足要求。

**视觉验收**：完成同视口真实截图对比，明显偏差已修正；剩余项目有原因和用户决定。原始字体不可得或素材只能近似重建时，必须明确记录。

任何未完成截图或页面运行验证的任务，都不得给出视觉验收通过结论。
