# 首阶段详细拆解、用户审核与坐标规格

## 不可跳过的执行顺序

先读取原图并完成整图与局部分析 → 在聊天中呈现下面的八段说明 → **停止本轮，等待用户审核** → 用户纠正时更新并重审 → 得到明确批准后才固化工程规格、制作素材和写页面。

不得以用户一开始要求“帮我复刻”“完整实现”“快速做”为理由跳过审核。分析产物可以直接在聊天中展示，不要求写文件；不得只给 JSON、文件链接或抽象计划。分析时仅允许经授权的观察网格与局部图，不生成正式角色素材、不写骨架、不启动制作型图片任务。

## 必须向用户展示的八段固定格式

按原图实际内容填写；没有的项明确写“无／暂不需要”，未知项写“待核验”，不照抄示例。复杂图片可分区表述，但不能漏掉主要区域和重要素材。

### 1. 目标与画布

- 原图实际宽高、比例；信息来自文件读取还是估算。
- 类型：A 静态宣传图 / B 真实 UI / C 混合场景。
- 建议 CSS 视口、DPR、最终物理截图尺寸及理由；尚未批准时明确写“建议”。
- 可编辑、可交互、响应式要求，以及固定画布与实际应用的区别。

### 2. 画面分区与布局关系

按从上到下、从左到右拆出主区域，说明各区域大小比例、位置、留白、对齐、重复结构、遮挡和旋转。为主要元素使用稳定 ID；不能只写“标题、卡片、插画”，而要交代数量和相互关系。

| 区域／元素 ID | 可见内容与数量 | 位置、比例、对齐与层级 | 关键样式 | 是否清楚／待核验项 |
|---|---|---|---|---|
| 按原图填写 | 保留实际顺序 | 估算要注明 | 颜色、边框、圆角等 | 不猜测被遮挡内容 |

### 3. 逐项实现分工（审核重点）

每个主要视觉元素必须有一行或明确的重复分组；不能只笼统说“混合实现”。

| 元素 ID／所在区域 | 准备采用的方式 | 为什么不用其他方式 | 素材来源与当前可执行能力 | 风险／替代方案 | 需要用户决定 |
|---|---|---|---|---|---|
| 按原图填写 | HTML/CSS、SVG、复用素材、原图裁切、AI抠图/编辑、AI生图或待定 | 分辨简单几何与复杂笔触 | 说明已有文件、可提取像素、是否缺工具 | 不承诺精确重建未知字体/遮挡 | 标明图片化和近似生成许可 |

使用以下明确分类，避免模型把“提取”混为一谈：

- `html-css`：真实文字、卡片、容器、简单背景及交互组件。
- `svg`：明确、简单的矢量轮廓；复杂手绘笔触不默认手工 SVG 临摹。
- `reuse-image`：已有独立原素材，不重新生成相似替代品。
- `crop-image`：能保留原始像素的矩形裁切；裁切不等于透明抠图。
- `remove-background`：需要 AI 抠图／图片编辑／人工去背景；说明轮廓、前景白色及毛发风险和工具可用性。
- `generate-image`：原素材缺失或不完整且代码不适合时的近似补足；先提议，未批准不生图。说明比例、透明需求、留白、遮挡补全及外观不一致风险。
- `undetermined`：证据不足；列出需要用户确认的事项，不自行选一个方式动工。

### 4. 文字与字体

按区域转录可辨认文字，保留标点、顺序和换行；小字裁剪后核对，模糊处单列。区分 OCR 候选和已核验内容。列出普通／交互文字的真实文本方案、装饰性标题的字体可得性及图片化备选。必须可编辑的文字不能图片化；特殊标题图片化需要逐项许可和可访问文字说明。

### 5. 图片素材与工具需求

列出需要的独立素材、源区域、裁切或抠图步骤、目标比例、显示尺寸、透明边界和单独验收方式。明确“哪些先提取、哪些需要抠图、哪些才考虑生图”。没有生图需求时写“本图暂不需要 AI 生图”；缺工具时写“当前不可执行，需要补充工具或原素材”。不把 Alpha 检查脚本说成抠图工具。

### 6. 不确定项与高风险偏差

按影响排序，列出主布局、特殊字体、微小文字、角色遮挡、复杂纹理、透明边缘等实际风险；每项说明证据、未知内容和确认方法。不承诺不同字体／系统下完全像素一致。

### 7. 批准后的实施顺序与检查方法

给出简短顺序：固化规格 → 素材单项验收 → 布局骨架 → 文字与素材集成 → 固定视口截图 → 几何／素材文字／细节局部校正。说明先检查哪些关键区域，什么情况下重新请求用户决定。

### 8. 审核请求与当前状态

明确“当前仅完成分析，尚未制作正式素材或编写页面”。单列必须确认的视口、代码／图片分工、近似生成和装饰字图片化。结尾使用：

> 请审核以上拆解，尤其是代码与图片素材的分工。可以指出需要修改的项，或确认按本方案继续；我会在收到确认后再制作素材和实现页面。

只批准局部就只实施局部。收到纠正意见后说明修订版本和差异，重新等待批准；批准实施策略不等于批准最终素材或精确坐标。

## 观察副本与坐标换算

在批准的输出目录运行，绝对路径替换为实际路径：

```bash
python "<技能目录>/scripts/prepare_reference.py" --input "<项目目录>/reference/source.png" --output-dir "<项目目录>/reference/preprocessed" --grid-step 100 --scale 2
```

默认生成 `grid.png`、九宫格区域图和 `regions.json`；复杂元素跨格时，用 `--regions` 自定义命名区域，保留整图上下文，不能把格子边界当元素边界。网格只用于分析，不进入页面。原图为 JPEG 等时保留原文件，经授权生成同尺寸 PNG 观察副本；脚本不直接解码 JPEG，不能静默缩放。

统一使用源图像素、左上原点、像素边界半开区间。元素位置是**绝对源坐标**，`parentId` 只表示布局层级，不改变坐标原点。放大裁图上的测量必须逆变换：

```text
source.x = region.x + local.x / scale
source.y = region.y + local.y / scale
source.width = local.width / scale
source.height = local.height / scale
relative.x = source.x / sourceWidth
relative.y = source.y / sourceHeight
relative.width = source.width / sourceWidth
relative.height = source.height / sourceHeight
```

用 `prepare_reference.local_to_source(region, x, y, width, height, scale)` 计算，不让模型心算，保留小数。前端固定画布在 DPR 不为 1 时，用源坐标除以 DPR 得到 CSS 坐标，截图物理尺寸等于 CSS 视口乘 DPR。旋转元素记录 `rotation` 和 `transformOrigin`，必要时记录顶点；浏览器 AABB 不等于旋转前布局框。

## 批准后固化的机器规格

完整文件格式、审批回执和校验命令见 `workflow.md`。至少记录：

- 画布与参考图摘要、方案版本和 `coordinateSpace: source-pixels`。
- 每个元素的 `id/type/parentId/x/y/width/height/rotation/implementation`。
- `source: measured|estimated|derived|user-provided`、`confidence: high|medium|low`、`verified`、核验证据。不要因用户说“继续”把所有估算改为 `verified: true`。
- `status: unimplemented|implemented|pending-review|approved`、`freeze`；只有实际验收后的元素才冻结，冻结要有证据。
- 文字清单的内容、识别来源、真实文本／图片化、可编辑要求及核验状态。
- 素材策略和未确认范围。关键区域位置与字体未知仍保持风险，不藏入已确认测量。

## 两个执行示例

**正确：**复杂混合图中主标题拟用真实文本，卡片用 CSS，角色拟从原图抠图，背景纹理拟裁切；说明抠图工具是否可用、特殊字体是否缺失、生图是否需要，展示八段说明，停下等待。用户说“角色不要生成，先提取，其他按方案继续”后只做已批准路径。

**错误：**看完图就写出页面，随后说“猫咪我用 CSS 画了个相似的”；或分析中建议抠图，未等回复就调用生图；或用生成的近似角色冒充原素材。即使代码能跑，也违反首阶段门禁。

## 复核清单

检查各主要区域和角色数量、文字漏项、裁切／抠图区别、代码与图片分工、工具能力、源坐标逆变换、低置信度项及用户批准范围。所有未知项保持待核验；八段说明未呈现或未获明确确认，不进入制作阶段。
