# 视觉逆向分析规格

## 分析任务

只分析参考图，不编写代码。输出必须让后续实现者能够定位元素、核验文字、选择素材策略并安排校正顺序。

## 分析预处理

保留原图，不压缩、不覆盖。复杂图片先生成带坐标网格的分析副本、命名分区裁剪和区域清单，让模型分别处理整图结构与局部细节。辅助网格和坐标文字只用于分析，不进入最终页面。

经用户确认输入和输出目录后，可运行：

```bash
python scripts/prepare_reference.py --input "reference/source.png" --output-dir "reference/preprocessed" --grid-step 100 --scale 2
```

默认输出 `grid.png`、`regions.json` 和 `regions/` 下的九宫格裁剪。已有明确分区时，通过 `--regions` 传入自定义区域 JSON；区域记录必须包含稳定 ID 和原图矩形坐标。放大只能帮助观察，不能恢复原图中不存在的信息。

预处理失败时保留原图并改为人工分区，相关细节标记未验证；不得声称已经生成网格或裁剪材料。

## 输出结构

A. 画布规格：原图宽高、宽高比、目标类型、建议视口和设备像素比。

B. 页面布局树：画布、主区域、子区域、面板、卡片、文字、图片和装饰的层级。

C. 元素坐标与样式表：稳定 ID、类型、像素坐标、相对坐标、层级、遮挡、颜色、边框、圆角、阴影、字体、行高、对齐，以及来源、置信度和核验状态。

D. 独立文字清单：保留原顺序、标点、大小写和换行，记录识别来源、是否人工核验、字体与换行状态；不确定内容标为待核验。

E. 素材清单：位置、用途、目标比例、透明背景需求、实现方式和建议文件名。

F. 待确认问题：只列会影响实现或验收的事项。

G. 误差风险：按视觉影响排序，说明哪些估算最需要截图校正。

## 坐标与置信度

元素 ID 使用稳定、可读且唯一的名称，例如 `title-main`、`panel-primary`、`character-01`。后续差异报告和修正必须复用同一 ID。

- `high`：边界、文字或样式直接清晰可见。
- `medium`：主要信息可见，但尺寸或字体存在少量估算。
- `low`：遮挡、模糊或信息缺失，必须经用户或截图核验。

置信度不等于核验状态。每项至少同时记录：

- `source`：`measured`、`estimated`、`derived` 或 `user-provided`，说明数据从何而来。
- `verified`：是否经过原图测量、人工检查或截图对比；未核验估算不得进入“已确认规格”。
- `status`：`unimplemented`、`implemented`、`pending-review` 或 `approved`。
- `freeze`：已验收元素是否需要防止后续误改；只有确需保护时设为 `true`。

局部裁剪中的坐标必须加上裁剪偏移，换算为原图坐标。旋转卡片、倾斜手机框和斜切装饰还要记录 `rotation`，必要时记录 `transformOrigin` 或关键顶点，不能只保留包围盒。

以下 JSON 展示格式，数值不是任何实际图片的测量结果：

```json
{
  "canvas": {
    "sourceWidth": 1536,
    "sourceHeight": 864,
    "viewportWidth": 1536,
    "viewportHeight": 864,
    "deviceScaleFactor": 1
  },
  "elements": [
    {
      "id": "title-main",
      "type": "text",
      "text": "示例标题",
      "x": 90,
      "y": 18,
      "width": 820,
      "height": 120,
      "relative": {
        "x": 0.0586,
        "y": 0.0208,
        "width": 0.5339,
        "height": 0.1389
      },
      "style": {
        "fontSize": 96,
        "fontWeight": 900,
        "lineHeight": 1.1,
        "color": "#222222"
      },
      "zIndex": 10,
      "rotation": 0,
      "source": "estimated",
      "confidence": "medium",
      "verified": false,
      "status": "unimplemented",
      "freeze": false,
      "evidence": "标题可见；字体和精确边界待截图校正"
    }
  ]
}
```

相对坐标以原图宽或高为分母。不要用相对坐标掩盖像素估算的不确定性。

## 独立文字清单

普通印刷体可使用宿主已有 OCR 或用户提供的 OCR 结果，再人工核对；小字先裁剪放大，手写内容无法确认时保留待核验。OCR 只负责候选文字，不直接决定字体、颜色、位置或换行。

```json
{
  "title-main": {
    "text": "示例标题",
    "source": "ocr",
    "verified": false,
    "fontSource": "estimated",
    "fontVerified": false,
    "fontSize": 96,
    "fontWeight": 900,
    "lineHeight": 1.1,
    "color": "#222222",
    "lineBreaksVerified": false
  }
}
```

字段值仅展示格式。`verified: false` 的文字不得悄悄变成最终定稿；用户确认后再更新状态，并保留实际使用的字体或回退情况。

## 实现方式分类

为每个元素选择一种主要方式，并说明原因：

- `html-css`：文字、卡片、边框、简单背景和可交互区域。
- `svg`：轮廓明确、颜色有限的图标和曲线。
- `extract-image`：可从原图或已有资源提取的复杂插画与纹理。
- `approved-reconstruction`：用户同意后的近似重建素材。
- `undetermined`：信息不足，列出需要核验的内容。

## 可直接复用的分析提示词

```text
你是 UI 视觉逆向工程师。只分析我提供的参考图片，为后续高保真前端复刻生成可执行规格，不写 HTML、CSS 或 JavaScript。

以参考图片为唯一视觉目标，不创意改版，不优化布局，不改变文字、配色或元素关系。

1. 记录原图宽高、宽高比、A/B/C 任务类型和建议复刻视口。
2. 结合整图、坐标网格和当前分区裁剪分析；局部坐标换算为原图坐标，不把辅助网格当成页面内容。
3. 分解画布、主区域、子区域、卡片、文字、图片和装饰层级。
4. 为每个可识别元素分配唯一 ID，给出 x、y、width、height 像素坐标和相对坐标；旋转元素补充角度或顶点。
5. 记录间距、对齐、层级、遮挡、边框、圆角、阴影、颜色、字号、字重和行高。
6. 转录全部可辨认文字，保留顺序、标点和换行；无法确认时标记待核验，不猜测。
7. 将元素分类为 html-css、svg、extract-image、approved-reconstruction 或 undetermined。
8. 每项记录 source、confidence、verified；估算不得写成已测量事实。
9. 输出独立文字清单和素材清单，记录核验状态、位置、用途、比例、透明背景需求和建议文件名。

按 A 画布规格、B 布局树、C 元素坐标与样式、D 文字清单、E 素材清单、F 待确认问题、G 误差风险输出。
```

## 分析复核

进入实现前检查：

- 标题、主要面板和复杂插画都有唯一 ID。
- 文字没有漏项、乱序或未经标记的猜写。
- 主区域的坐标和比例彼此一致，没有明显重叠矛盾。
- 所有低置信度关键项都已列入待确认问题，未核验估算没有混入已确认规格。
- 文字清单中的识别来源和人工核验状态明确，没有把 OCR 候选直接当成定稿。
- 目标视口与原图尺寸的关系已说明。
- 复杂素材已有提取或重建策略，没有默认全部用 CSS 或全部用图片。
