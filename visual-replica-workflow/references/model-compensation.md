# 能力不稳定模型的执行补偿

## 基本原则

按实际模型、版本、图片类型和错误表现选择补偿，不笼统认定国内模型都弱。目标是减少一轮要猜的事实、降低任务规模，并用实际证据发现错误，而不是把总提示词不断加长。

**首次八段详细分析与用户审核不可跳过，快速路径只减少非关键精修或可选模型测试，不能提前写页面、抠图、生图。** 固定说明见 `analysis-spec.md`，文件格式和校验接口统一见 `workflow.md`，不要自己另造一套字段。

## 任务分级与错误分流

| 情形 | 默认策略 |
|---|---|
| A 静态宣传图 | 固定画布、混合素材；特殊字图片化需批准 |
| B 真实应用 UI | 核心文本与交互真组件，按目标视口布局 |
| C 宣传图嵌 UI | 分区决定代码、SVG、图片与交互，不统一整图处理 |
| 漏细节或遮挡 | 整图定位后，逐区裁剪；一轮不同时分析所有区域 |
| 空间估算不准 | 网格、明确坐标空间、脚本逆变换与浏览器 AABB；保留估算状态 |
| OCR／字体不稳定 | OCR 候选与文字核验独立，字体未知不冒充原字体 |
| 素材边界不准 | 原素材优先、实际抠图工具、Alpha 和深浅背景验收 |
| 生图改变角色或伪透明 | 生成许可单列，角色逐项审批，失败不擅自改为相似替代 |
| 文件缺失、路径混乱 | 固定接口、根相对文件路径、单文件任务与实际文件检查 |
| 多轮修复退化 | 局部任务卡、版本化截图、文件检查点、冻结回归 |
| 自我评估不可靠 | 独立浏览器截图与实际对比，未验证不宣称完成 |

## 默认任务规模

- 分析：先整图分区，再逐个命名区域检查；用户收到的是完整八段说明，不是遗漏内容的缩略分析。
- 素材：一次一个独立角色或一小组同类图标；复杂去背景与生成分开，结果单独审核。
- 骨架：先主区关系，不混入字体、阴影和精细角色任务。
- 编码：一次一个组件或文件，先固定接口和共享变量；输出被截断时只续写该文件，不重写全工程。
- 修复：默认一次一个区域、最多三个相关问题。扩大范围须明确理由、批准范围和回归范围。
- 冻结：已验收区域不随手改；父容器、共享规则间接影响也要回归。

每一任务用下面的短卡，不重复装载全部参考文档：

```text
本轮阶段与任务ID：
当前参考图／分析版本与用户批准范围：
输入材料：当前区域原图、当前截图、差异图、相关规格／文字／素材
只需完成：一个区域／组件／文件，最多三个相关问题
允许修改：实际文件、元素ID、选择器与属性
必须保留：已确认布局、素材、冻结区域
输出：变更清单、实际证据、未核验项
停止：缺输入、缺审批、发现范围冲突或证据不可信
```

先诊断再修复；诊断角色只写实际差异、证据和候选原因，不直接重写项目。代码角色仅执行明确问题，不提出主观美化。

## 最小上下文包与换模型续接

第一阶段无需强制创建文件，直接聊天分析和审核即可。批准后的工程轮次提供：

- `analysis.json`：当前规划、来源、状态和审核回执；规划摘要由工具计算。
- `text-manifest.json`：涉及文字的候选、核验、字体和图片化许可。
- `asset-manifest.json`：本轮实际存在素材、路径、来源与审批。
- 本轮原图局部、最新 `round-NN.png`、配对 `.capture.json`、差异局部。
- `issues.json`：允许元素／文件／属性和回归范围。
- 实际相关代码、组件接口与必需共享样式；不反复塞全部历史。

缺材料明确写缺失，不凭聊天记忆补造。切换模型时携带相同方案版本、实际用户确认、未完成项和最新证据。`checks_passed` 只表示机器一致性，不能作为新的用户确认；部分批准不得扩大为全部批准。

## 两轮无改善时的处理

连续两轮同一类问题无改善或出现退化，暂停扩张：

1. 检查原图和截图是否同尺寸、同状态、同字体条件，不先怪 CSS。
2. 缩小到单元素，提供原图／实现／差异三联图和可追溯坐标。
3. 查明是坐标转换、字体回退、透明留白、素材本身还是共享规则影响。
4. 必要时更换识别或实现分工；不无限要求“再优化整页”。
5. 更改目标方案或引入近似资源时重审；用户接受已知差异时记录具体区域和取舍，而不是自动称 1:1。

## 可选模型准入测试

仅在新模型、新图片类型或持续识别错误时，且用户愿意测试时执行。用户明确把测试留到以后，则不执行，也不把未做写为通过；主流程仍保持详细分析和审核。

| 小任务 | 用户／工具提供的事实基准 | 记录什么 |
|---|---|---|
| 内容识别 | 实际元素数量、中文标签、顺序 | 漏项、错字、错误分类 |
| 网格定位 | 几个已测量元素的源坐标 | 偏差和坐标空间混淆 |
| 差异诊断 | 局部截图中几处已知改动 | 漏报、误报、猜测原因 |

记录具体模型版本、图片类型、输入区域、实际错误和后续分工。不要用没有真实基准的模型自评分；两个模型猜同一坐标也不等于测量。

## 失败与降级

预处理失败可人工分区；OCR 不可用可视觉候选加人工核验；没有抠图／生图工具则说明资源缺口；无法自动截图可请求同视口手动截图。明确区分未完成自动检查、部分验证和用户人工复查，不编造结果。

严格脚本就绪检查与最终视觉检查都需要实际执行；脚本不具备工具授权的证明能力，也不会把像素差异归零作为质量指标。用户选择降级时保留原约束和具体未验证项，不阻碍可用阶段，也不偷换已批准方案。
