# 素材处理与前端实现

## 素材决策

| 元素 | 优先方式 | 核验重点 |
|---|---|---|
| 标题、正文、编号 | HTML 真实文本 | 字体、字号、换行、字距、可编辑性 |
| 卡片、面板、边框、手机外框 | HTML/CSS | 尺寸、圆角、阴影、层级 |
| 重复角色卡片和标签 | 可复用组件 | 统一尺寸与间距，不改变视觉 |
| 人物、动物、复杂角色 | 原素材或独立透明 PNG | 轮廓、表情、毛发、透明留白 |
| 简单图标、曲线 | SVG | 笔画、节点、比例和颜色 |
| 复杂涂鸦与纹理 | 提取图片 | 边缘、分辨率、平铺或裁剪 |
| 装饰性复杂内屏 | 独立图片 | 是否需要交互、裁剪区域 |
| 可交互内屏 | 真实组件 | 状态、点击区域和内容完整性 |

不要把所有装饰都拆成图片，也不要强迫所有内容变成 CSS。决定依据是视觉复杂度、交互需求、可维护性和原素材可用性。

## 素材处理顺序

1. 搜索用户明确提供的项目素材目录，复用原始文件。
2. 从参考图提取时保留原图，不覆盖源文件；记录裁剪坐标与输出尺寸。
3. 去背景后检查透明通道和边缘，不把白色角色主体误删，不损失细线、耳尾和毛发。
4. 统一素材内容框，记录透明留白；前端显示时使用明确宽高和 `object-fit`，避免拉伸。
5. 原图缺少独立素材时，先报告缺口。用户同意近似重建后才生成，并在清单中写明 `approximate: true`。
6. 多个角色分别处理，不把十几个角色合成一张图后再切割。

逐个 PNG 素材进行机器检查，经用户确认输出目录后运行：

```bash
python scripts/inspect_assets.py --asset "public/assets/characters/captain.png" --output-dir "reviews/assets/captain"
```

输出 `inspection.json` 和 `preview-light-dark.png`。脚本可以核验真实透明像素、内容边界和透明留白，但不能代替用户检查耳尾、毛发、表情和细线。棋盘格是否被画成普通像素、边缘是否自然，要结合深浅背景预览判断。

素材清单至少包含：

```json
{
  "character-captain": {
    "file": "assets/characters/captain.png",
    "source": "extracted",
    "sourceRegion": {"x": 0, "y": 0, "width": 0, "height": 0},
    "usage": "底部角色插画",
    "displaySize": {"width": 0, "height": 0},
    "aspectRatioLocked": true,
    "transparentBackground": true,
    "alphaVerified": false,
    "edgeChecked": false,
    "approximate": false,
    "approved": false,
    "notes": "待用户检查深浅背景预览"
  }
}
```

坐标和尺寸为零的字段表示尚未测量，不得直接用于实现。`alphaVerified` 只记录机器检查状态，`edgeChecked` 和 `approved` 需要实际看图或用户决定；未批准素材不能被后续模型当作可随意替换或已确认资源。

## 布局选择

固定画布宣传页可使用设计尺寸容器，再按用户确认的规则整体缩放：

```css
.replica-canvas {
  position: relative;
  width: 1536px;
  height: 864px;
  overflow: hidden;
}

.replica-canvas__item {
  position: absolute;
  box-sizing: border-box;
}
```

绝对定位适合主要视觉元素，Grid 适合规则卡片列表，Flexbox 适合卡片内部。三者分层配合，不因使用组件或布局系统改变设计坐标。

真实响应式应用应根据目标视口设计断点、流式尺寸和内容重排。整页缩放只能用于用户确认的固定画布，不得冒充响应式实现。

## 受约束的编码顺序

开始前固定技术栈和版本、目标视口、组件接口、共享视觉变量和素材路径。不得擅自换框架、猜测不存在的素材文件，或让不同实现者自由编写相互冲突的全局样式。

1. 输出项目结构、页面分区和素材引用表，先检查缺失文件与接口冲突。
2. 实现画布、背景、主要面板与整体定位，形成主区域和层级正确的结构版本。
3. 实现重复卡片、标签和标题等组件，加入文字、边框和背景样式。
4. 只集成已批准素材，修正内容框、透明留白和裁剪。
5. 检查字体加载、字体回退、换行、层级和遮挡，再处理阴影与精细装饰。
6. 启动页面，处理缺失资源和关键控制台错误。
7. 在相同视口下截图，再进入差异修正。

每次交付列出修改文件、完成事项和待检查事项；当前阶段未通过检查，不继续扩大实现范围。长代码需要分文件生成时，先固定组件接口和共享变量，不分别自由生成整页。

为关键元素保留稳定 class 或数据标识，与分析 ID 对应。把颜色、间距、圆角、字体等共享值集中维护。

## 局部修改任务卡

收到截图反馈后先诊断，再修改。每轮在 `issues.md` 固定范围：

```text
目标元素：
可见问题及证据：
允许修改的文件、组件和 CSS 属性：
禁止修改的冻结元素和已批准素材：
修改后的目标、相邻和冻结区域回归范围：
```

只修改任务卡列出的内容。确需调整冻结元素时，先说明原因和回归影响，不把局部问题扩成整页重写。修改完成后列出全部变更，等待重新截图，不提前宣布修好。

## 可直接复用的编码提示词

```text
基于参考图片、已核验视觉分析规格和素材目录实现高保真前端页面。

以参考图片为唯一视觉目标，不改版、不美化、不添加未经要求的元素。遵守目标视口、画布尺寸、元素坐标、比例、层级和文字内容。

优先复用已有素材，不擅自生成相近插画。复杂插画用图片，简单几何用 CSS 或 SVG，文字使用真实文本节点。不得把整张参考图设置成页面背景冒充复刻。

先输出结构与素材引用表，再完成布局骨架，随后实现重复组件并接入已批准素材，最后处理文字和视觉细节。每次只交付当前阶段，列出修改文件和待检查事项。关键元素使用与分析 ID 对应的稳定选择器，共享视觉值集中维护。

后续修正只处理 issues.md 中列出的元素、文件和属性，不修改冻结区域或替换已批准素材。完成后启动页面，记录启动方式、缺失资源和关键控制台错误。在参考图相同视口下截图，并列出尚未达到目标的视觉差异。没有实际截图时明确写未完成视觉验证，不宣称 1:1。
```

## 实现复核

- 页面没有整图背景或不可编辑的大块文字截图。
- 复杂素材来源可追溯，近似素材均已获得同意并标记，集成素材具有明确批准状态。
- 图片没有异常拉伸，透明留白未被误当作内容尺寸，Alpha 检查和人工边缘验收没有混为一谈。
- 主要元素可通过稳定 ID 定位，差异报告能映射回代码。
- 字体加载失败时有记录，没有把回退字体结果当作原字体。
- 页面启动方式和依赖说明完整，运行失败时明确标为未验证。
