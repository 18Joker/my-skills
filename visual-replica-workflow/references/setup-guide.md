# 环境、可选能力与恢复

## 能力边界

技能不自带大模型、OCR、精细抠图或生图服务。宿主提供图像理解、代码生成及需要的图片工具；本地脚本提供 PNG 预处理、透明检查、差异、项目校验和浏览器截图。默认不安装软件、不收账号或凭据、不新增 MCP 配置。

首次详细分析和用户审核可以直接在聊天中完成，不因缺少自动截图工具而跳过或阻塞全部分析。缺工具时明确说明哪部分不能执行；实际素材制作与编码仍要等用户批准。

## Python 运行时

- 本地脚本使用 Python 3.10 或更高 3.x。PNG、环境发现与项目校验使用标准库；严格截图后端额外需要已安装的 Python Playwright，不能再声称全部后端仅用标准库。
- Python 官方入口：https://www.python.org/downloads/ ，Windows 文档：https://docs.python.org/3/using/windows.html 。安装由用户决定，不自动下载。
- PNG 范围：8 位非交错灰度、RGB、索引色及带 Alpha 的常见类型；不解码 JPEG／WebP／16 位／交错 PNG。保留原文件，转换副本需确认，不隐式缩放。
- 缺 Python 时可继续宿主视觉分析和人工核验，但自带预处理、Alpha、差异及项目机器校验未执行，不伪造证据。

## 本地浏览器与可选严格后端

浏览器发现同时检查 PATH 与 Windows／macOS 常见 Chrome、Chromium、Edge 安装位置，环境检查和截图器共用发现逻辑。**发现可执行文件不证明无头启动成功、Python Playwright 已安装或页面就绪。**

Chrome 下载入口：https://www.google.cn/intl/zh-CN/chrome/ ，无头文档：https://developer.chrome.com/docs/chromium/headless 。优先宿主已有浏览器，避免重复配置。需要登录的页面交由用户明确授权的宿主会话，不收个人账号数据。

- `--backend playwright`：需要已安装且支持本脚本使用 API 的 Python Playwright，以及发现的本地浏览器；使用该浏览器，不下载其捆绑浏览器。安装或版本兼容由用户选择和实际运行核验。
- Python Playwright 官方说明：https://playwright.dev/python/docs/intro 。不自动执行安装，不猜具体最新版本。
- `--backend cli`：仅本地浏览器命令行，生成有效新 PNG 与尺寸证据；无法检查字体、DOM、页面错误和稳定性，报告明确未验证。
- `--backend auto`：按已可用 Python Playwright 选择，否则 CLI；严格运行失败不自动更换后端并抹去故障。
- 实际截图会启动临时隔离无头浏览器，不使用个人浏览器 profile；HTTP／HTTPS 页面会访问其请求资源，本地 file 页面也可能包含远程资源，不承诺绝不联网。
- 总进程预算固定 45 秒，操作超时或兼容失败保留 structured 故障，不能无限重试或声称有效截图。

具体参数、报告与降级结果见 `verification.md`。没有实际运行，浏览器兼容与严格后端只能标记待用户测试。

## OCR、抠图与生图

OCR 由宿主已有能力或用户提供结果，不自动安装识别服务。记录 `source: ocr|vision|user-provided`，候选文字必须核验。没有 OCR 可通过局部图候选加用户校对，不编造 OCR 输出。

抠图／图片编辑与生图以工具实际能力为准。没有对应工具时说明资源缺口，优先用户原素材或可准确裁切区域；只能近似重建时先取得元素级许可。`inspect_assets.py` 只能核验透明通道与内容边界，不会抠图、去背景、重画角色或恢复被遮挡像素。

## 路径、输出与审批

- 使用绝对脚本路径；机器清单中的文件引用以批准工程根为基准、用正斜杠，不混用浏览器 URL。
- `validate_project.py` 只读取明列工程内文件，拒绝 `..` 和符号链接逃逸；审批版本与摘要校验不能证明真实用户授权，宿主仍核对实际聊天消息。
- 输出目录先获得授权；已有输出默认停止，覆盖必须明确许可。图片输出保护输入及其符号链接／硬链接别名；截图与报告不能共同原子发布，配对须核对 PNG 摘要。
- 出现权限、坏 PNG、截图尺寸或报告不匹配时，停止受影响阶段、保留原图与实际错误。不扫描个人目录寻找替代目标，不删除项目来修复环境。
- 没有账号凭据需要轮换；如用户撤销环境，通过正常卸载或撤销目录授权处理，不删除 `.workbuddy-ai` 或项目文件。

## 用户自行测试入口

按用户要求可以仅完成技能修改与结构打包，把运行测试留给用户。不要把此前版本的测试通过等同当前版本通过。已有扩展离线测试保留在 `tests/test_workflow_scripts.py`，用户准备测试时可自行运行：

```bash
python -B "<技能目录>/tests/test_workflow_scripts.py" -v
```

实际工作流建议先检查：首次是否完整给出八段说明并停下；用户纠正后是否更新而不动工；批准后是否保留原素材优先；每轮是否提供新截图并说明剩余差异。随后自行验证严格截图、异常资源、局部修改与冻结回归。

这些是待运行的入口，不是已执行记录，不在交付中写“全套测试已通过”。
