# 公告生成（Announcement Generator）

## 概述

把用户提供的「公告主题 + 细节」加工成一份**发布级 markdown 公告文档**。产出遵循当前项目公告系统的字段校验规则与历史文案风格，用户可直接复制到公告管理后台发布，无需二次修改。

## 工作流

### 第 0 步：收集需求

- 明确三要素：**主题**（什么事的公告）、**类型**（update / dev_talk / important / urgent / survey，用户未指定时按下方「类型选择」推荐）、**细节**（功能点、上线时间、补偿方案、行动指引、问卷链接等）。
- 细节不足时先向用户确认，**禁止编造功能细节、时间、补偿内容**。
- 若用户只给主题没给细节，基于项目已知能力（能量系统、免广告、排行榜、文字记牌、角色套图等）提出合理的可写范围并请用户确认。

### 第 1 步：核对字段规范

- 读取 `references/announcement-schema.md`，掌握字段、类型、action、治理规则、有效期。
- 若工作区可访问且公告云函数可能有更新，用 CodeGraph（`codegraph_explore`，projectPath 指向项目根目录）核实 `cloudfunctions/announcement-admin/index.js` 的最新校验逻辑，以代码为准。

### 第 2 步：参考历史风格

- 读取 `references/historical-style.md`，提炼语气、结构、emoji、标题/摘要写法规律。
- 让公告"像这个产品发出来的"，而非通用模板腔。

### 第 3 步：撰写公告

- 按类型选择语气与模板（见下）。
- 标题 ≤ 30 字、摘要 ≤ 80 字（可带 emoji 点缀），正文 markdown 分节、关键信息加粗。
- 正文用词亲切真诚，玩家向，符合产品一贯口吻（"各位鹅友、鸭友们好！"、"祝大家把把神预判、局局抓对鸭！🦆"）。
- **默认配置加群动作**：每条公告默认附带 `action: { type: 'join_group', label: <按钮文案> }`，**按钮文案（label）随主题一并生成**——活动/福利类 →「加入用户群领福利」；问题/补偿类 →「加入用户群反馈」「联系管理员」；交流/预告类 →「加入交流群提建议」；通用 →「加入官方交流群」。仅当用户明确不需要按钮时省略，并在交付时说明。

### 第 4 步：自检清单（对标后台校验逻辑）

- [ ] 类型 ∈ `update | dev_talk | important | urgent | survey`
- [ ] 标题非空且 ≤ 30 字
- [ ] 摘要 ≤ 80 字
- [ ] update / dev_talk / important / urgent 必须有正文（`content_md`）
- [ ] urgent 正文必须包含「影响 / 恢复 / 预计 / 时间」相关表述（如"对您的影响""预计恢复时间"）
- [ ] survey 必须配置 action：`type=survey` 且 payload 为外部问卷链接
- [ ] action：**默认应为 `join_group` 且带 label（按钮文案）**；仅当用户明确不要按钮时省略；若为 link/survey 必须带 payload
- [ ] 有效期：默认 15 天（`expire_time = publish_time + 15天`），超长有效期需用户确认
- [ ] 置顶（pin）：全库已置顶 ≥ 2 条时不可再置顶，需提示用户先下架旧置顶
- [ ] 紧急公告：当日已发过 urgent 会被自动降级为 important，写之前提示用户

### 第 5 步：交付

- 输出完整 markdown 文档：**发布参数表**（type / title / summary / pin / action，action 默认 `join_group` 且带已生成的按钮文案 label）+ **正文 markdown**（可直接复制）。
- 告知用户：正文粘贴到公告管理后台（announcement-admin）的 content 字段，参数按表填写即可发布。
- 文档落盘：按项目文档规范放入 `docs/` 对应目录（公告类内容归 `04-运营推广/` 或 `10-版本迭代/`，以实际内容判断），或询问用户指定位置。文件名以当天日期为前缀。

## 类型选择

| 场景 | 类型 | 语气 |
|---|---|---|
| 功能/版本上线、规则调整说明、bug 修复说明 | `update`（更新公告）| 正式但不生硬 |
| 预告、坦白运营成本、福利活动、道歉补偿、开发者心声 | `dev_talk`（开发者说）| 亲切、坦诚、有温度 |
| 重要但不紧急的通知 | `important`（重要通知）| 稳重 |
| 线上故障、紧急影响 | `urgent`（紧急公告）| 先致歉、讲影响、给恢复时间 |
| 收集意见 / 调研 | `survey`（调研投票）| 请求帮助的口吻，附问卷链接 |

## 通用结构模板

1. **称呼**：各位鹅友、鸭友们好！/ 亲爱的玩家朋友们：
2. **背景点题**：1-2 句说明为什么发这条公告。
3. **分节详情**：`###` 小节 + `-` 列表 + `**加粗**` 关键信息；功能类用「1. 2. 3.」编号。
4. **行动指引**：加用户群 / 反馈 / 领取方式，正文中引导点击 action 按钮（如"点击下方【加入用户群】按钮"），按钮文案随公告目的生成。
5. **收尾**：感谢 + 祝福（如"祝大家把把神预判、局局抓对鸭！🦆"）。

## 语气与风格要点

- 亲切真诚，玩家向，不说教、不端着。
- 问题类公告：先道歉 → 说明原因 → 补偿方案 → 致谢。
- 福利类公告：突出价值与领取方式，简单直接，不绕弯。
- emoji 适度：🎁🌟📢💡⚡🔋✨🛠️💬🚀🔧 用于标题/小节/关键点点缀，正文不滥用。
- 避免空话套话；能用具体数字（"7 天免广告""15 点能量"）就用数字。
